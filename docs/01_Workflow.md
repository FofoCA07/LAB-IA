# Workflow Oficial de LAB-IA

Versión: 1.0

---

# Objetivo

Este documento define la metodología oficial de trabajo dentro de LAB-IA.

Todo proyecto desarrollado utilizando este laboratorio debe seguir este flujo.

El objetivo es mantener un proceso consistente, reproducible y fácil de entender.

---

# Filosofía

LAB-IA no busca reemplazar al desarrollador.

Busca convertirlo en un mejor desarrollador.

Los agentes existen para acelerar el aprendizaje, automatizar tareas repetitivas y mejorar la calidad del software.

---

# Flujo General

Todo trabajo sigue el siguiente orden:

Idea

↓

Planificación

↓

Implementación

↓

Revisión

↓

Depuración

↓

Entrega

↓

Documentación

---

# Selección del agente

Cada agente tiene una responsabilidad específica.

Nunca elegir un agente por costumbre.

Elegirlo según la tarea.

---

Profesor

Objetivo:

Aprender.

Uso recomendado:

- Nuevos conceptos
- Preparación para exámenes
- Explicaciones
- Ejercicios guiados

---

Senior Developer

Objetivo:

Construir soluciones.

Uso recomendado:

- Nuevos proyectos
- Implementaciones
- Refactorizaciones
- Arquitectura

---

Reviewer

Objetivo:

Encontrar problemas.

Uso recomendado:

- Antes de hacer commit
- Antes de entregar proyectos
- Antes de desplegar

---

Debugger

Objetivo:

Encontrar la causa raíz.

Uso recomendado:

- Errores
- Bugs
- Excepciones
- Problemas de configuración

---

SQL Expert

Objetivo:

Bases de datos.

Uso recomendado:

- SQL Server
- PostgreSQL
- Diseño
- Optimización

---

Docker Expert

Objetivo:

Infraestructura.

Uso recomendado:

- Docker
- Docker Compose
- Permisos
- Redes
- Contenedores

---

Prompt Engineer

Objetivo:

Mejorar el laboratorio.

Uso recomendado:

- Crear agentes
- Corregir agentes
- Mejorar prompts
- Diseñar comportamientos

---

# Regla Principal

Antes de modificar cualquier proyecto:

1. Leer.
2. Entender.
3. Planificar.
4. Implementar.
5. Verificar.

Nunca modificar archivos sin comprender primero el contexto.

---

# Reglas de trabajo

Siempre:

- Leer el proyecto antes de modificarlo.
- Trabajar únicamente dentro del workspace.
- Evitar asumir rutas.
- Evitar soluciones improvisadas.
- Priorizar cambios pequeños.
- Documentar cambios importantes.

---

# Checklist antes de terminar

□ El código compila.

□ El proyecto funciona.

□ El Reviewer no encontró problemas críticos.

□ El Debugger verificó los errores.

□ La documentación fue actualizada si fue necesario.

□ El proyecto está listo para entregar.

Fin del Workflow Oficial de LAB-IA.
